# Письмо Деду Морозу — готовый проект

Сайт адаптирован для телефонов, планшетов и компьютеров. Письма отправляются через Resend API на `osipoveriko@gmail.com`. Пароль/API-ключ не хранится в браузере.

## Что нужно сделать
1. Создать аккаунт Resend и получить API Key.
2. Добавить API Key и адрес получателя в переменные Render.
3. Опубликовать проект на Render через GitHub.

Для аккаунтов и настройки детского сайта попросите родителя/опекуна помочь. Не публикуйте сайт для детей до согласования с ответственным взрослым правил обработки данных и получения надлежащего согласия родителей/опекунов. Галочка в форме сама по себе не является юридическим подтверждением согласия.

## Шаг 1. Resend
1. Откройте https://resend.com/ и создайте аккаунт.
2. Подтвердите адрес владельца аккаунта.
3. Откройте API Keys: https://resend.com/api-keys
4. Создайте ключ с правами отправки писем (Sending access), скопируйте его. Он показывается при создании — сохраните его в надёжном месте.
5. В этом проекте отправитель по умолчанию `onboarding@resend.dev`. Тестовый отправитель Resend ограничен правилами тестового режима: обычно можно отправлять только на подтверждённый адрес владельца аккаунта. Поскольку получатель `osipoveriko@gmail.com`, аккаунт Resend должен быть зарегистрирован/подтверждён этим адресом. Для отправки на произвольные адреса нужен собственный домен, подтверждённый в Resend, и другой `MAIL_FROM`.

## Шаг 2. Загрузить проект в GitHub
1. Откройте https://github.com/ и создайте репозиторий, например `pismo-dedu-moroz`.
2. Загрузите все файлы и папку `public` из этого архива в репозиторий.
3. Не загружайте файл `.env` и никогда не публикуйте API-ключ. В архиве есть только `.env.example` без действующего ключа.

## Шаг 3. Render
1. Откройте https://render.com/ и создайте аккаунт.
2. В панели Render выберите New → Blueprint (или создайте Web Service из GitHub).
3. Подключите репозиторий с проектом. Файл `render.yaml` уже содержит настройки сборки и запуска.
4. При создании Blueprint Render попросит задать `RESEND_API_KEY`: вставьте ключ из Resend.
5. Проверьте переменные окружения:
   - `RESEND_API_KEY` — ваш секретный ключ Resend;
   - `MAIL_TO` — `osipoveriko@gmail.com`;
   - `MAIL_FROM` — `onboarding@resend.dev` для разрешённого тестового режима.
6. Нажмите Deploy. Дождитесь статуса Live. Render выдаст адрес вида `https://имя-сервиса.onrender.com`.

Если Render не позволяет создать Blueprint на бесплатном тарифе или просит подтверждение, создайте Web Service вручную:
- Runtime: Node
- Build Command: `npm install`
- Start Command: `npm start`
- Добавьте три переменные выше.

## Шаг 4. Проверка
1. Откройте выданную HTTPS-ссылку.
2. Заполните тестовое письмо с согласия родителя/опекуна.
3. Отправьте его и проверьте Gmail, включая папку «Спам».
4. Если Resend сообщает, что адрес получателя не подтверждён или отправитель запрещён, проверьте подтверждение аккаунта и ограничения тестового режима. Для реального публичного использования настройте собственный домен отправителя и подтвердите его в Resend.

## Локальный запуск (не обязателен)
1. Установите Node.js 18 или новее: https://nodejs.org/
2. Скопируйте `.env.example` в `.env`.
3. Вставьте API-ключ в `RESEND_API_KEY`.
4. Выполните в терминале:
   ```bash
   npm install
   npm start
   ```
5. Откройте http://localhost:3000

## Как изменить сайт
- `public/index.html` — заголовки и поля формы.
- `public/style.css` — оформление и адаптация.
- `public/app.js` — отправка формы.
- `server.js` — сервер и почтовая отправка.

## Бесплатный тариф и ограничения
Бесплатный хостинг может переводить сервис в сон после периода бездействия, поэтому первое открытие иногда медленнее. Условия бесплатных планов меняются — проверьте актуальные лимиты на сайтах провайдеров. Бесплатный тестовый отправитель Resend не равен полноценной массовой рассылке: для публичного запуска может потребоваться собственный домен, подтверждение домена и соблюдение лимитов сервиса.

## Приватность детей
Форма запрашивает имя, возраст и текст желания. Не добавляйте сбор адреса, телефона, школы, фамилии или фото. Сообщите родителям, кто получает письма, для чего они используются и когда удаляются. Установите срок хранения писем и регулярно удаляйте ненужные сообщения. Прежде чем открыть сайт широкой аудитории, попросите взрослого проверить требования применимого законодательства о данных детей и получить необходимое согласие.
